# DXF → KML

ابزار تبدیل فایل DXF به KML، به‌طور کامل در مرورگر اجرا می‌شود (بدون نیاز به سرور یا بک‌اند).

## راه‌اندازی روی GitHub Pages

1. یک ریپازیتوری جدید در گیت‌هاب بسازید (مثلاً به نام `dxf-to-kml`).
2. فایل `index.html` را در ریشهٔ همان ریپازیتوری آپلود کنید (از طریق "Add file → Upload files" یا با `git push`).
3. به بخش **Settings → Pages** ریپازیتوری بروید.
4. در قسمت **Source**، شاخهٔ `main` و پوشهٔ `/ (root)` را انتخاب کنید و ذخیره کنید.
5. بعد از حدود یک دقیقه، سایت روی آدرسی شبیه این در دسترس خواهد بود:
   `https://<username>.github.io/dxf-to-kml/`

نیازی به هیچ مرحلهٔ Build یا نصب پکیج نیست؛ چون همه‌چیز (پردازش DXF، ساخت KML، نقشهٔ پیش‌نمایش) با جاوااسکریپت خالص و کتابخانهٔ Leaflet (از طریق CDN) در همان صفحه انجام می‌شود.

## سیستم مختصات

در بخش تنظیمات صفحه، دو حالت قابل انتخاب است:

- **UTM** (پیش‌فرض): باید شمارهٔ زون (۱ تا ۶۰) و نیمکره (شمالی/جنوبی) را وارد کنید. مختصات X و Y فایل به‌عنوان Easting و Northing خوانده می‌شوند و با فرمول استاندارد تبدیل UTM → WGS84 (روی بیضی‌وار WGS84) به طول/عرض جغرافیایی تبدیل می‌شوند. این تبدیل کاملاً در مرورگر انجام می‌شود و نیاز به اینترنت یا سرویس خارجی ندارد.
- **جغرافیایی (WGS84)**: برای فایل‌هایی که از قبل مختصات X/Y آن‌ها طول/عرض جغرافیایی است.

اگر زون اشتباه انتخاب شود، ابزار به‌طور خودکار هشدار می‌دهد (چه بر اساس بازهٔ معمول مقادیر Easting/Northing، چه بر اساس خروج نتیجهٔ نهایی از بازهٔ معتبر طول/عرض جغرافیایی).

## محدودیت‌های فعلی

- عناصر پشتیبانی‌شده: `LINE`, `POINT`, `CIRCLE`, `ARC`, `LWPOLYLINE`, `POLYLINE`, `TEXT`, `MTEXT`.
- عناصر پیچیده‌تر مثل `INSERT` (بلوک‌ها)، `SPLINE`، `HATCH` و ابعادگذاری (`DIMENSION`) در حال حاضر پشتیبانی نمی‌شوند.
- سیستم‌های مختصات دیگر (مثل State Plane یا سیستم‌های محلی/دلخواه) پشتیبانی نمی‌شوند؛ فقط UTM و WGS84.
